# v0.2 library ergonomics adversarial review

## TypeScript application developer

The default exports now lead with `createCaudex`, `createProgram`, measurement
helpers, and methodologies. A recommendation no longer requires schema versions
or repeated catalog values, success branches narrow normally, and set completion
requires only a set ID. The first pass still required persistence merely to
accept proposed state; this violated the optional-persistence boundary and was
fixed so acceptance can remain local to a program facade. Reload deliberately
returns a fresh active-workout facade and set lookup uses its current snapshot,
which makes stale behavior explicit.

Follow-up: `Program.replaceHistory()` and `appendCompletedWorkout()` now make
authoritative history changes explicit without requiring facade reconstruction.

## Zig library consumer

Ownership remains visible: requests borrow catalog arrays and `Output` owns all
bounded result storage. The artificial one-exercise rejection was removed and a
clean external consumer now executes a two-exercise typed recommendation. The
fixed output is larger, but its `max_recommended_exercises` bound is public and
there is still no allocation or builder lifetime. TypeScript-style workflow
objects were not copied into Zig.

Follow-up: generic host methodologies can now use `TypedRecommendationRequest`
and `recommendTyped` with caller-owned issue, scratch, and output storage. The
specialized first-party request remains available and unchanged.

## C/FFI integrator

ABI v2 symbols, version, ownership, sizing calls, statuses, and the canonical
execution envelope are unchanged. New TypeScript conveniences do not leak into
the header. The contract now states why the asymmetry is intentional. C remains
a compact deterministic protocol engine and existing conformance consumers
continue to compile and run.

## Follow-up implementation review

Application-context construction moved into `application.ts`, and WASM loading,
Node/browser resolution, ABI checks, and export validation moved into
`wasm-runtime.ts`. Active-workout lifecycle, set resolution, and completion
persistence moved into `active-workout.ts`. The entry module now concentrates
on public contracts, canonical dispatch, and top-level workflow assembly.
Multi-exercise Zig recommendations
assign unique bounded explanation IDs and references for every exercise instead
of omitting later explanations.
